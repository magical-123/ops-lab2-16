## 测前预测与实际执行

测前预测原文保留在 [A-O1-plan.md](A-O1-plan.md)，于 `e925c69db91e02cab504b19d39ef71425a34c3a8`（2026-10-28 00:02:59 +08:00）提交。该提交是两组 `meta.txt` 记录的 `dab739e` 的祖先；预测未在测后修改。预测是 GC 次数减少、RSS 上升，GC CPU 与 p99 可能降低，但不保证。

实际在共享目录 `/srv/lab2` 顺序运行 GOGC=100、400，各先预热 10 秒，再正式测量 60 秒。服务分别重启，PID 为 612750、614574；Go 均为 1.27.3、GOMAXPROCS=1，服务绑 CPU 1，客户端绑 CPU 0。两个逻辑 CPU 在来宾系统中属于同一 CORE，不能当作完全隔离的物理核。请求均为 `GET http://127.0.0.1:8080/api/report?mb=4`，每次分配并触碰 4 MiB 临时内存，返回小 JSON。

正式命令由各次 `meta.txt` 保存：

```bash
GEN_CPUS=0 scripts/run.sh o1-gogc100 \
  -url 'http://127.0.0.1:8080/api/report?mb=4' -rates 100 -step 60s
# 重启为 GOGC=400 后，运行名改为 o1-gogc400，负载参数相同。
```

`loadgen.log` 确认 Poisson 到达、2 秒超时、客户端 GOMAXPROCS=1。命令未覆盖随机种子，源码默认值为 1。预热分别在 [o1-100-warmup](../runs/o1-100-warmup/) 和 [o1-400-warmup](../runs/o1-400-warmup/)，各成功 998 次，不加入正式结果。

## 统计口径与解释边界

- 客户端完整阶段为 60 秒。GC 快照在负载开始前、结束并额外等待 1 秒后读取；服务器原始文件完成时间差分别为 **61.020714067 s、61.020712653 s**，包括采集准备和排空，不称为精确的 60 秒 GC CPU。时间来源另存 [provenance.json](../runs/o1-evidence/provenance.json)，文件完成时间也不是原子指标读取时刻。
- RSS 查询去掉阶段前 5 秒，区间分别为 `[1793283923,1793283978]`、`[1793284182,1793284237]`，均为 **55 秒跨度、56 个等间隔 1 秒求值点**，与辅助 RED/USE 的窗口一致。Prometheus 查询可能复用最近抓取值；56 个求值点不等于证明有 56 个独立抓取。均值是这些点的算术均值，峰值只表示保存点的最大值，不是进程整个阶段的瞬时高水位。
- 客户端 p99 统计成功请求，从计划发送时间算起，已包含发送滞后；不再额外加 `lag_p99_ms`。两组均无失败，因此本次不存在成功样本筛选引起的错误请求遗漏。
- `go_gc_cpu_seconds_total` 来自运行时 `/cpu/classes/gc/total:cpu-seconds`，是可能高估、包含空闲标记成本的估计值；不等于 GC 暂停，也不直接与操作系统进程 CPU 秒计算占比。[runtime/metrics](https://pkg.go.dev/runtime/metrics) 说明了这一限制。本实验没有暂停分布，不能说“GC 暂停缩短了 75%”。
- 实际每种设置只有一次，顺序未交错。由 `meta.txt` 与预热、正式 `steps.csv` 可算出：启动至预热分别等了 245 / 10 秒，预热结束至正式阶段分别等了 4 / 41 秒，堆与归还页状态可能受这些时序影响。`meta.txt` 记录当时工作区有 5 / 7 处未提交改动，未保存完整环境与构建哈希，也未保存结束时的 `/config`。现有记录支持本次对照观察，不能把 p99 变化全部归因于 GC，或推广为所有负载下的固定收益；未将后来准备但未运行的多轮协议写成实测。

与 L-06 第 12 页 JVM 堆与 GC 的联系是：更大的可用堆增长空间通常允许较低回收频率，以更多内存换取较少回收成本；内存更紧时则需更频繁地回收。Go 的 GOGC 按上次存活堆与 GC 根控制目标增长比例，和 JVM 的最大堆参数不是同一个参数；提高到 400 不意味着 RSS 必然变为四倍。本次 RSS 均值约为原来的 2.30 倍，符合“内存换回收成本”的方向。[Go GC Guide](https://go.dev/doc/gc-guide#GOGC) 给出了目标堆与 GOGC 的关系。
